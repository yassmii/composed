# Optional model assignment

The kit's assignment policy is portable agent guidance, not a routing engine. It preserves the
current native-delegation gate and fresh non-author review where required. External execution can
be recorded, but cannot count toward that gate until a separately qualified integration is released.
No provider, profile, gateway or runtime installation is required to use the kit.

## Preferences belong to the project

No configuration is required. In a session without model selection, use the available model within
existing authority; improve the brief, context and scheduling. Do not report a requested model as
selected when the runtime cannot select it. A small correction stays direct with relevant checks
inline and no new artifact.

When useful, add prose to the existing project-owned `.agents/project-instructions.md`. It is read
by installed bridges and preserved by init/update. These are symbolic examples, not parsed runtime
configuration and not a credential store.

One available model:

```markdown
## Agent/model preferences
Use the session's available model for all authorised work. Model selection is unavailable.
Keep observed identity unknown unless returned by the runtime. Run the project's relevant checks.
For complex work, delegate useful native missions and retain required independent review.
```

Optional profiles and approved gateway/local launch configuration:

```markdown
## Agent/model preferences
These aliases are local intentions, not evidence of availability or competence:
- fast: model-short; suitable for bounded fixture inspection when verified tools permit it.
- standard: model-main; default for ordinary implementation within its observed capabilities.
- deep: model-main; use supported effort controls for high-risk analysis, if exposed.
Approved launch configuration: see the project owner's local runtime configuration.
Credentials and private endpoints remain outside work traces.
Non-exportable data must stay local; do not replace a local backend with a remote service.
Remote synthetic tasks may use the approved gateway within the authorised session budget.
If a requested profile/model is unknown or unavailable, report it; select an alternative only
within existing authorisation. No automatic provider, backend or model fallback.
```

Applicable user and project constraints come first, then session choices within that scope, then
local defaults. Speed preferences cannot overrule privacy, permissions, acceptance or review. One
model may serve several profiles; a profile name is not a guarantee and effort is runtime-specific.

## Worked decisions

| Situation | Assignment and evidence |
| --- | --- |
| Known typo, no selector | Direct edit using the available model; relevant existing check inline. No profile lookup, agent registry or new work folder. |
| Independent implementation lots, one model | Useful native missions with isolated writes; same model is valid. Integrator advances shared work and validates integrated changes. Fresh non-author review remains separate. |
| Multiple authorised models | Filter tool, data, permission and availability constraints first, then observed task-family capability/preferences. State a prudent choice when history is absent; no model tournament. |
| Risky API change | Suitable capability from the outset, bounded consumer evidence and required independent review. Do not try a cheaper unsuitable model before taking the risk seriously. |
| `fast` requested but absent | Report unavailable/unknown. Use an authorised alternative if available; otherwise block that assignment. Never invent selection. |
| Local-only data, local agent unavailable | Block dependent transmission. Remote speed or a configured gateway does not permit export. |
| Permission denied or repeated failure | Capture the cause and choose an access/tool/brief/scope remedy. A more powerful model does not grant permission. Respect attempt and spending limits. |
| Agent says finished but tests fail | Execution can be complete; deliverable validation fails. Return to the owner with evidence. |

## Bounded brief and existing trace

A useful mission names outcome, relevant sources, constraints, write ownership, exit criteria,
result format and an explicit attempt limit. For example: inspect fixture X and the relevant
parser; implement the missing empty-input case only in `src/parser` and its tests; run the named
native check; return changed files, check results and gaps; at most two attempts before reporting
the cause and next owner. Parallel writers need isolated worktrees or verified disjoint access;
branches alone do not isolate writes. Reuse context when suitable, except for fresh review.

Where delegation evidence is already required, extend the existing `agents.md` entry, for example:

| Field | Example |
| --- | --- |
| Mission / assignment reason | Empty-input parser fix; bounded implementation matching observed capability |
| Execution mode / runtime ID | `native-subagent` / actual returned ID |
| Requested model / observed model | `model-main` / `unknown` if not independently exposed |
| Workspace / access | Isolated worktree path and verified read/write scope |
| State / available duration | Terminal execution state / `unknown` if not exposed |
| Result / evidence | Changed files, actual check result, artifact references and remaining gaps |

For external runs record `external-agent` and its actual run ID without counting it toward the
native gate. A gateway can obscure identity: the requested name is never evidence of the observed
backend. Missing cost, usage, effort and duration remain unknown. Do not copy full prompts, secrets
or private endpoints. Process completion, agent declaration and deliverable validation stay distinct.

Rerun checks after relevant changes rather than reusing stale evidence. Diagnose before escalation;
change the brief, tools, decomposition or model according to the failure. No identical retry loop,
automatic remote fallback or spending beyond the authorised envelope. These instructions alone do
not prove runtime behaviour or a speed gain; real-session observations are required.
