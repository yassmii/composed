# Technology reference consumer and maintenance rules

- Read selection.md before recommending a stack. Preserve contract neutrality and existing choices.
- Treat catalog statements as scoped research, never as conformance or measured performance.
- Use current primary sources for decisive claims; do not refresh dates without reviewing claims.
- Cite contract clause IDs and technology capability/source IDs in project decisions.
- Record missing coverage, stale sources, unknown compatibility and license constraints explicitly.
- Keep monitoring observations separate from semantic review; a successful HTTP response proves neither.
- Maintain this component's CHANGELOG independently. Validate here with the root technology scripts.
- Do not copy the catalog into installed Build Kit packages or silently update consumer decisions.
