# Proportionate delivery and runtime readiness

Authorisation: user accepted autonomous implementation of the first two follow-up priorities after
the paired pilot. Reuse existing Node/TypeScript CLI, bilingual skills and bridges; no product stack
change, new dependency, benchmark/model campaign, package publication or runtime supervisor.

Outcome: known small corrections stay direct with proportionate native validation; complex work keeps
actual native delegation and independent review. Runtime checks distinguish observed path-write
capability from unknown delegation/review/quota capability instead of inferring readiness from install.

Included delivery artifacts:
- Explicit execution shape separate from risk in catalog, FR/EN doctrine and relevant skills/docs.
  A bounded direct fix must have known requirements, local impact, no material security/API/data/stack
  change, no cross-agent/session handoff and no user-requested durable plan/review. Inline scope and
  validation suffice; do not downgrade risk or waive an explicit review to obtain this path.
- A dependency-free `preflight --write-path <project-relative directory>` CLI (repeatable, bounded)
  that performs exclusive temporary create/write/read/remove probes in actual intended paths,
  removes only its owned empty directories, refuses links/outside/metadata destinations and reports
  failures/cleanup limits. Invocation through the agent's actual sandbox/tool matters. Never changes
  permissions, project files, bridges or external configuration. Standalone process cannot verify
  session delegation, reviewer independence or account quota; those remain explicitly unknown.
- Runtime startup instructions require actual native checks only where the task needs them, avoid
  repeated probes after success in the same unchanged context, and block the affected action on
  missing required capability. No silent path relocation, sandbox bypass or multi-agent fallback.
- Three concrete examples (small correction, feature, complex work), meaningful filesystem/CLI tests,
  independent skill forward exercise and distinct non-author final review.

Deferred: product lifecycle/knowledge-service expansions, optional Composed Runtime, generic remote
capability attestation, paid calls/telemetry and confirmation tuning. Existing benchmark evidence,
contracts, source version and immutable tags remain unchanged. Release notes stay under Unreleased.

Method: delivery-orchestrator coordinates, skill-creator guides instruction revision, engineering owns
CLI, independent native agents audit/validate. Parent owns canonical integration and final checks.
Parallel authors require distinct worktrees; read-only audit may share canonical source. Exit: actual
positive/negative probes, appropriate component checks and fresh non-author accepted review.
